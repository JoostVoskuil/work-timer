# WorkTimer

Local-first macOS menu-bar work-hours tracker. No network, no cloud, no screenshots, no keystroke content. Activity is stored as five-minute category totals, not app-switch history.

Requires macOS 27 or later and Xcode with the macOS 27 SDK to build.

The app uses native macOS sidebar navigation, a unified window toolbar, system typography and Liquid Glass action buttons. Work, Private and Learn retain consistent teal, purple and blue indicators. Reports show Work-only targets separately from the combined Work + Learn weekly ceiling.

WorkTimer appears in the Dock while its main window is open. Closing the window hides the Dock icon but keeps tracking and the menu-bar timer running; use Quit to stop the app. **Open WorkTimer** in the menu brings the window and Dock icon back.

Only while Pomodoro is counting down, the menu bar shows its remaining minutes and seconds, updating every second without additional database writes. Focus and break phases have distinct icons. Paused, completed, and stopped timers show the WorkTimer tracker icon instead; timer details remain available in the menu and Pomodoro screen. The Pomodoro screen has just two controls: **Start/Stop** (Space) starts focus, stops (pauses) a running phase, continues a stopped one, or starts the offered break after a finished focus; **Reset** returns to a fresh focus phase at the configured length (default 25 minutes; set it under Settings → Pomodoro) and restarts the break cycle, showing the tracker icon again. Storage errors remain visible in the menu bar.

The countdown uses an isolated display clock and plain text, not `TimelineView` or live date text in the menu-bar label. Each second refreshes only the countdown, reading the existing monotonic Pomodoro timer; it does not refresh the activity screen or write to SQLite. The display clock stops when paused, completed or stopped.

Clicking the menu-bar icon opens a Today dashboard and refreshes it immediately, including when macOS reuses the popup window. It shows whether today is a scheduled working day (or a day off), whether the current time is within work or private hours, and the actual tracked category separately so overrides and private rules remain clear. Hourly Work/Private/Learn bars cover 06:00–23:00; a full-day activity-mix graph also includes Break, Away and Unknown. Daily totals, Work target, remaining time and balance use the same corrected/live five-minute accounting as reports and widgets. Totals include hidden sleeping hours. Graph data refreshes on the normal tracking cadence only while the popup is visible; Pomodoro's one-second display stays isolated. The dashboard shows the **Normal mode** (Work or Private hours from your schedule) next to the **Manual mode** you chose, if any, and when it ends. Auto, Private, Work and Learn mode buttons stay visible below the scrollable dashboard, with the active one highlighted, along with Open and Quit. Mode changes do not pause tracking, and there is no manual tracking-pause button.

## Build and run
- `swift test` (the test target passes the Swift Testing macro-plugin path needed with Command Line Tools only).
- `./scripts/build-app.sh` produces `build/WorkTimer.app` (ad-hoc signed). Copy it to `/Applications`, open it, and allow notifications.
- To build, install and start the full app with its widget and Safari extensions, install XcodeGen (`brew install xcodegen`), set your Apple Developer Team ID, then run `TEAM_ID=YOUR_TEAM_ID ./scripts/watch-install.sh`. It watches app, widget, Safari extension, package and test sources; each detected edit rebuilds, replaces `/Applications/WorkTimer.app` and restarts it. Use `TEAM_ID=YOUR_TEAM_ID ./scripts/watch-install.sh --once` to install and launch without watching. Stop the watcher with Ctrl-C. Set `INSTALL_DIR` only if you deliberately want another installation folder.
- The app bundle identifier is `nl.foxhole.worktimer`, with `.widgets` and `.safari` extension identifiers. The Xcode build uses automatic signing and may ask Xcode to provision the configured team. All targets use the macOS App Group `TEAM_ID.nl.foxhole.worktimer.shared`, expanded from `DEVELOPMENT_TEAM` into their entitlements and Info.plists; this team-prefixed format does not require portal registration. The installer refreshes Launch Services, explicitly registers the embedded widget extension, and the app calls `WidgetCenter.reloadAllTimelines()` on launch. You still need to add the WorkTimer widget from Notification Center's **Edit Widgets** screen. Safari extensions must be enabled in Safari settings.
- When updating from the old `nl.worktimer.app` identity, the profile database and history remain in place. The app republishes derived widget data into the new App Group. macOS treats the renamed bundle as a new app: notification permissions may need granting again, widgets may need re-adding, and the Safari extension may need enabling again.
- Outside-hours activity defaults to **Private**, without a notification or review task. Use **Private**, **Work**, or **Learn** in the menu to switch to a manual mode immediately, inside or outside working hours, without stopping tracking. A manual mode overrides app/website rules (Safari private browsing always stays Private) and survives idle, lock and sleep; Away time still applies. It ends at the next start or end of working hours, when you press **Auto**, or when WorkTimer quits. Notifications are used for work-hour limits, Pomodoro and the test button.

## Data
- Stored in your user profile: `~/Library/Application Support/WorkTimer/worktimer.sqlite` (plus `Backups/`). Backups are plain SQLite and **not encrypted**.
- Schema 2 stores one compact record per observed five-minute block. Reports credit each block to exactly one category for five full minutes. Internal duration counters and observed coverage are retained only to determine the winner reliably as tracking continues and to support corrections, recovery and Undo; switch history is not stored. There are at most 288 canonical blocks per 24 hours (276/300 on a 23/25-hour local day), regardless of app-switch frequency. Entirely unobserved blocks are not created.
- App and Safari domain rules still classify activity live. Each new block also retains a deduplicated set of observed app bundle identifiers; Today resolves them to readable app names where available. Hover a block's app list to see each app's name with its bundle ID; right-click it to copy a bundle ID or add an **Always classify as Work/Learn/Private** app rule. In Settings → Classification rules, choose **App bundle ID** and use **Choose app** to pick from apps seen in the last two weeks or currently running, or **Browse Applications…**; app rules are listed by name and bundle ID. (In Terminal, `osascript -e 'id of app "Outlook"'` also prints an app's bundle ID.) Domains, window titles, per-app durations and app-switch timestamps are not stored. The bounded provisional tail carries category durations and block-local app sets for retroactive idle detection and crash recovery. Checkpoints normally update every 15 seconds, rather than on every app activation, and finalized blocks are committed together.
- History was converted to blocks after a verified original backup. Old corrections are part of the baseline and cannot be individually undone; **Settings → Health** retains the original backup location. Archival backups retain original app/site detail until you deliberately delete them.
- Conversion code has been removed. New databases are created directly with schema 2, and existing block databases open unchanged. Only current-format block backups can be restored. Legacy databases/backups are rejected without conversion; use the earlier WorkTimer version to convert them first. Existing data and archival backups are not deleted.
- Run `/Applications/WorkTimer.app`, not older copies from another folder. An atomic, profile-local lock allows only one instance to track, including simultaneous launches from different locations; additional instances exit. The lock is released automatically on quit or crash.
- The app also publishes its widget summary to the shared App Group container, using the same location resolver as the widget. The database stays in the user profile. Successful publication requests a timeline reload on launch and at most every 15 minutes thereafter; macOS controls refresh timing.
- **After an update** the app republishes the widget snapshot and asks WidgetKit to reload all timelines. The version is recorded only after success.
- Deviation from the plan: the system SQLite3 library is used instead of GRDB (no dependencies).

## Accounting definitions
- During configured working hours, the category with the most recorded time wins the entire five-minute block: four minutes Work and one minute Private becomes five minutes Work. Outside working hours, any recorded Work wins, even when another category occupies most of the block. Without Work, the longest category wins. Idle is combined with Away before comparing durations.
- Ties favour Work, then Learn, Private, Break, Away and Unknown. A block touching a scheduled work window uses the working-hours rule; wholly outside-hours blocks (including weekends) use the Work-first rule. Partially observed and current blocks also count as five minutes; a current block's winner can change until it is complete.
- The same rule applies to existing history, Today, reports, graphs, widgets, limits and CSV, after correction overlays. No destructive conversion is needed; original counters and backups are preserved.
- Work = classified work time; Private, Break, Away and Unknown are excluded. Outside-hours time is confirmed Private by default, not pending.
- Five minutes without input reclassifies the period since the last input as Away, clipped to configured working hours. It does not create a review task. Correct completed blocks in Today if you were working on a call.
- All inactivity (idle, sleep, screen lock, inactive session and paused tracking) is recorded as Away only within the configured work window. Outside that window it is omitted, not relabelled as Private.
- Away corrections are limited to recorded coverage within working hours. Historical database cleanup preserves mixed or corrected blocks when removing inactivity would risk other activity or Undo history; its backup is listed in Settings → Health.
- Week-to-date balance = work Monday..selected day minus scheduled targets for those days (today's full target counts and is labelled "incomplete").
- One calculator (`ReportCalculator`) feeds the menu bar, reports, widget snapshot and CSV.
- Pending review totals include only unknown time covered by actionable gap reviews: at least 15 contiguous minutes within a working window. Shorter gaps and unknown time outside work windows remain excluded from work but are not pending.
- Report charts stack Work (teal), Private (purple) and Learn (blue), with a legend. Private includes private rules, private browsing and ordinary outside-hours activity. Private never contributes to work balances. App/domain attribution reports are intentionally no longer available.
- Learn (blue) is a separate category, not contractual work. Choose **Learn** in the menu bar to start a learning session; choose **Work** or **Private** to leave it. You can also classify Review items or timeline entries as Learn. Learning sessions respect private rules, idle, sleep, lock and break exclusions and end when the app restarts.
- Work + Learn share the weekly ceiling (45 hours by default). Reports, the menu and widgets show the combined usage; a notification warns once per week when the ceiling is reached. Actual time remains recorded even above the limit, rather than silently truncated. Work targets and balances still use Work only. Summary CSV retains its columns, including `learn_h`; `idle_h` is zero because inactivity now counts as Away.
- **Export blocks CSV** replaces switch-level timeline export. Each row has block start/end, timezone, accounted seconds, Work/Learn/Private/Break/Away/Unknown seconds and pending seconds. Exactly one category has 300 seconds. The existing `observed_s` column now represents accounted block seconds, not raw observation duration. It contains no app/site attribution.

## Rule precedence
Rules classify an app or Safari domain as Private, Work or Learn. Domain rules beat app rules; on ties Private beats Learn, which beats Work. Existing rules keep their Work/Private meaning. Default private: nu.nl, nos.nl, tweakers.net, VLC. Hostname matching is exact or `.`-suffix (so `menu.nl` does not match `nu.nl`).

## Corrections
Today displays one category and five minutes per block. **Change → Mark block as …** explicitly chooses the category of a completed block. New corrections are overlays and support Undo, including overlapping edits; undoing a gap answer restores its review. A gap answer changes only underlying Unknown counters before the block winner is calculated, preserving known observations.

Use the previous/next-day arrows or date picker to browse earlier days, then **Today** to return to the live day. Totals, targets, balances, blocks and corrections follow the displayed date; menu-bar tracking, notifications and widgets continue to use the actual current day. Future dates cannot be selected.

Days off are managed in Today, not Settings. Check **Day off** next to the Work target to set the displayed day's target to 0 (uncheck to restore the schedule). **Days off** opens a list of all days off, where you can remove them or add any date, including future ones.

Completed blocks always have checkboxes; there is no separate selection mode. Check individual blocks, or Shift-click a checkbox to check or clear the range from the last ordinary checkbox click. Ranges include intervening recorded blocks, even inside collapsed Away groups; expand those groups to see their individual checkboxes. **Select all** selects only completed blocks on the displayed day. **Set category** applies to the selected blocks together: a failure leaves every selected block unchanged, unselected blocks are untouched, and each correction remains undoable. Changing the displayed day clears selection; unfinished blocks and outside-hours Away assignments remain protected.

Each block lists the apps observed during it, regardless of which category wins. This is an app list, not a claim about per-app time or usage order. Repeated switches do not duplicate entries. Corrections leave recorded app lists unchanged. Older blocks and inactive periods say **No apps recorded**; discarded historical app data cannot be reconstructed. Unknown or uninstalled apps fall back to their bundle identifier.

Consecutive completed blocks credited to Away (including idle time) collapse into one time range in Today. Expand the range to view or correct individual five-minute blocks. Live blocks remain separate, and absent blocks are never bridged. Grouping does not rewrite stored observations.

Manual entries use completed five-minute boundaries and a category you pick directly (Work, Learn, Private or Break). They replace every recorded block in their period, including its apps; undo the entry to restore the original blocks. Exact old sub-block correction history is available only in the pre-compaction backup, not as individual Undo actions after migration.

## Review
Review is exception-only: tracking was unavailable for at least 15 contiguous minutes within the configured work window. Adjacent unknown observations form one task rather than many switch-sized tasks. Known activity, work-window boundaries and separate days split tasks; overnight/weekend gaps do not create reviews. A new task may appear after its block data is committed.

Idle defaults to Away, outside-hours activity defaults to Private, and neither generates a task or automatic classification prompt. Explicit Work/Learn sessions and corrections remain available. Only block-level app sets are retained, not site context or switch history.

## Xcode extensions
`Extensions/` holds the Safari Web Extension (hostname only), its native handler, the WidgetKit widget and an XcodeGen `project.yml`. The SwiftPM-built app does not contain these extensions; use the XcodeGen watcher above for the full app. Widgets require the extension to be installed and added in Notification Center.
Both extensions enable App Sandbox, which macOS requires for PlugInKit discovery. The installer verifies that the installed widget appears in PlugInKit, rather than treating a successful registration command as proof of discovery. For desktop placement, right-click the desktop, choose **Edit Widgets**, and search for **WorkTimer**.

### Graph widgets
Choose **Daily graph** or **Weekly graph**, each available in medium and large sizes. The daily chart stacks activity by hour from 06:00 to 23:00, hiding sleeping hours (23:00–06:00) in the reporting timezone; its totals still include the full day, without deleting or reclassifying recorded activity. The weekly chart stacks Monday through Sunday and retains full-day totals. Work is teal, Private is purple, and Learn is blue, with separate hour/minute totals beneath each chart. The existing **Work hours** summary remains available.

Graphs use the reporting timezone, including daylight-saving changes, and the same corrected/live block accounting as Reports. Default outside-hours activity counts as Private; Away, Breaks and Unknown are not shown as classified activity. Empty charts say so rather than inventing activity, and snapshots older than 30 minutes show an outdated-data indicator. Gallery previews use example data only; placed widgets always use your published snapshot. All widget types receive refresh requests together, subject to macOS refresh scheduling.

## Not measured
CPU, memory and energy targets, 8-hour soak, DST on a real clock, real sleep/lock, Safari behaviour and widget refresh budgets need manual validation (plan section 10, milestones A and H).
